# 实时词云 · Live Word Cloud

一个纯前端的实时词云工具：打开页面 → 输入文字 → 词云即时生成，并支持多人各自输入、汇总成一张词云。

🔗 在线地址：https://dt2027.github.io/wordcloud/

## 功能

**词云**

- **实时生成**：输入即更新（250ms 防抖），无需点击
- **中文分词**：42,805 词常用词表（jieba 高频词 + 清华 THUOCL 信息科技词），
  配合 PMI 内聚度、上下文自由度、碎片依附规则三重判定，
  能正确切出「新能源汽车」「卷积神经网络」「监督学习」「知识图谱」这类长词，
  也不会出现「工智能正在改」「大模」「然语」这类碎片
- **自适应布局**：网格占用 + 椭圆螺旋排布，手机小屏也能铺满
- **完全本地**：分词与渲染全在浏览器完成，内容不上传服务器
- **浅紫主题**：浅紫底 + 白色卡片 + 深紫墨字，5 套配色都为浅底加深过，浅色屏幕上同样清晰
- 5 套配色、词数上限可调、悬停显示词频、点击复制词语

**多人协作：各自输入 → 汇总词云**

- 点「开启协作」生成房间，复制链接邀请伙伴；也可以直接打开带 `#r=房间号` 的链接加入
- **邀请链接点开即进房**：链接里的房间号会被直接解析，不用再点一次「开启协作」，进入后立刻出现提示，可以直接开始输入
- 房间内**每个人独享一个输入框**：你的输入只进你自己的槽位，别人的输入不会覆盖你，
  你的原文别人也看不到（只有你自己能编辑自己的框）
- 词云是**所有人内容的汇总**：分人分词后词频相加，越高頻的词越大（经典词云口径）
- 贡献者名单实时显示每个人的昵称、在线状态、词数与个人重点词
- 刷新页面不会丢自己的内容：浏览器本地保存一个稳定身份 ID，回来时自动认领回原槽位
- 基于 **Yjs CRDT** 做并发合并，多人同时输入互不干扰，各端最终收敛到同一份汇总结果
- 晚加入 / 掉线重连的成员会自动追平进度（retained 状态 + 周期性全量广播）

**提交板块：定稿与防丢**

输入框下方是「提交板块」，提交 = 一次明确的定稿动作：

| 模式 | 按钮 | 提交做的事 |
| --- | --- | --- |
| 协作 | 提交到房间 | 立刻落一份房间完整快照（retained），别人和后加入的人一定看得到；同时在贡献者名单上给这个人挂「已提交」标记 |
| 单人 | 保存到本机 | 写入本机存储，刷新或关掉页面再回来自动恢复 |

- **提交之后文本依然可以继续编辑**，改完再提交一次即可更新快照
- 提交后又改了内容 → 状态变「有修改待提交」，名单上的「已提交」标记同步撤掉，别人能看出你还在改
- 内容在后台**始终自动存一份本机草稿**，即使忘了点提交也不会丢
- **退出房间会自动提交一次**，最后一笔改动不会因为走得太快而没落进快照

**房间生命周期：退出后内存会不会释放？**

分两侧看：

- **浏览器侧**：会。退出房间时 Y.Doc 被销毁、MQTT 连接断开，本地内存立刻释放；
  你的文字还留在本机草稿里（`localStorage`），刷新或再回来都还在
- **服务器侧**：**原本不会**。房间的完整快照是 MQTT 的 retained 消息，会一直留在 broker 上，
  直到被显式抹掉。现在补上了这条清理链路：

| 触发 | 行为 |
| --- | --- |
| 最后一人离开房间 | 离开时广播一次 `probe`「还有人在吗」，没人应答就判定为空房 → 自动抹掉 broker 上的房间副本 |
| 点「解散房间」 | 立刻广播 `close` 通知房间里的所有人，并抹掉 broker 上的房间副本与在线状态 |
| 直接关标签页 | 同「最后一人离开」：房间里没有其他人时顺手清理 |

- 抹除用的是 MQTT 的「零长度 payload + retain」语义，broker 会真的删掉那条 retained 消息
- 房间被解散后，幸存成员的 15 秒周期同步**不会再把房间写回来**（`closed` 标志会拦住写回），
  所以房间不会被「复活」
- 「解散房间」是页面内二次确认（再点一次才生效，8 秒内有效），不用原生弹窗，避免误点
- 解散前会先把房间内容备份到本机（`wc-backup-<房间号>`），你的文字不会因为解散而消失

**词表导出**

页面底部是「高频词汇榜」表格（序号 / 词语 / 次数 / 提及人数 / 提及者），现场看词频用；
**导出的文件只有「词语」一列**，不含序号、次数、提及人数、提及者：

| 方式 | 说明 |
| --- | --- |
| 复制词表 | 每行一个词，直接粘到任何地方 |
| 导出 CSV | 带 UTF-8 BOM，Excel / WPS 打开不乱码，只有一列「词语」 |
| 导出 Excel | SpreadsheetML 2003 单文件 `.xls`，Excel / WPS 直接打开，只有一列「词语」 |

导出的词表是**所有人的汇总**（分人分词后合并去重，按总次数从高到低排序）；
原来还有一个「导出各人明细」，既然明细也只要词语、与汇总导出内容一致，已合并掉。

## 分词判定逻辑

一个 n-gram 要成为词，必须同时通过三关：

1. **内聚度（PMI）**：所有切分点的结合度都要足够高，即字与字之间结合紧密
2. **上下文自由度**：左右邻居的种类数。固定在同一种语境里出现的，多半是长词的一部分而非独立词；
   出现在句首也计作一种独立语境
3. **碎片依附规则**：若某词的所有出现都恰好是另一个更长词的前缀/后缀（如「工智」之于「工智能」、
   「然语」之于「然语言」），则判为碎片并丢弃；只有当那个长串本身也够格时（如「知识图谱」），
   才会顶掉词典里的短词（「知识」），避免把完整词组拆散

词典命中的词直接收录；未命中的词则要求更严的统计证据。
拿不准的低频词宁可漏掉，也不输出碎片。

## 同步协议

静态网站没有服务端，协作通过公共 MQTT over WebSocket 广播完成：

| 主题 | 作用 |
| --- | --- |
| `wc/<room>/doc` | retained，完整文档状态（base64），保证后加入者追平；**空房或解散时用零长度 payload 抹掉** |
| `wc/<room>/live` | 增量更新，或新成员加入时的状态请求响应 |
| `wc/<room>/req` | 新成员加入时广播的状态请求 |
| `wc/<room>/p/<id>` | retained，在线状态 `{name, ts}`；离开时用零长度 payload 删掉 |
| `wc/<room>/probe` | 有人离开时问一句「还有人在吗」 |
| `wc/<room>/pong/<id>` | 还在房间里的人应答（说明房间不空，不用清理） |
| `wc/<room>/close` | 房间被解散的通知，收到的人立刻切回单人模式 |

默认依次尝试 `broker.emqx.io` → `broker.hivemq.com` → `test.mosquitto.org`，
任一可用即可；也可在 `collab.js` 的 `DEFAULT_BROKERS` 里换成自己的 MQTT 服务，
内容就不会再经过第三方服务器。

## 本地运行

```bash
python -m http.server 8777
# 浏览器打开 http://localhost:8777/
```

> 调试建议用仓库外的 `dev/serve.py`（8779 端口）：它会发 `no-store` 头，
> 避免浏览器缓存住旧的 ES module 导致改动不生效。
> 另外所有模块引用都带 `?v=版本号` 参数，改动前端后要同步更新版本号，
> 否则线上用户可能拿到旧文件。

## 技术说明

- 无框架、无构建、无外部 CDN 依赖，离线可用
- Canvas 2D 绘制，按 devicePixelRatio 适配高分屏
- 排布算法：网格（6px）占用标记 + 预生成椭圆螺旋路径（约 12000 个候选位置），
  典型渲染耗时 30~90ms
- 每人槽位是 Yjs Map 里的一个独立 Y.Text，并发写不同 key 天然不冲突；
  本地改动与远端改动走同一条 diff 通路
